# How to comment

READI is a draft. Comments shape what the next dated version says.

1. [Open an issue](https://github.com/yolo-labs-hq/readi-standard/issues/new/choose) using the **Comment on the draft** form.
2. Say which part you’re commenting on: a level, a check, the check states, or a READI Access flow and requirement ID (for example `RA-2.3`).
3. Describe the problem or question in plain language. A real example helps most: a site, an agent, or a result that READI gets wrong.
4. If you have a fix in mind, suggest the wording.

Accepted changes are recorded in the next dated version of the draft.

Don’t report security problems in a public issue. A security contact is pending; see [readi.page](https://readi.page/spec#security-contact).
